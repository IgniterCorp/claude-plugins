# lit-deck — 문학·에세이 → 발표 deck

> **공통 규약을 먼저 읽는다** → [`_common.md`](_common.md)

독서모임·북클럽 발표용. `tech-deck` 과 **반대 작업**이다 —
기술서는 재구성이지만 문학은 **압축과 인용**이다. 줄거리를 다 말하면 발표가 아니라 스포일러다.

옵션: `level` · `density` · `minutes`

## tech-deck 과 무엇이 다른가

| | tech-deck | lit-deck |
|---|---|---|
| 핵심 재료 | 코드·개념·절차 | **인용** |
| 구조 | 주장 → 근거 | 장면·모티프 → 해석 |
| 줄거리 | 해당 없음 | **최소한만** — 1~2슬라이드 |
| 금지 | 코드 생략 | 결말 노출(사전 합의 없이) |

## ① 아웃라인

```
목표 슬라이드 수 = round(minutes × 0.6)      # 문학은 한 슬라이드에 머무는 시간이 길다
density simple → × 0.7   standard → × 1.0   full → × 1.3
```

| 칸 종류 | 수 | `chapterId` |
|---|---|---|
| 표지 — 제목·저자, 그리고 **이 발표가 던지는 질문** | 1 | null |
| 어떤 이야기인가 — 결말 없이 | 1~2 | null |
| **모티프·논점** — 한 칸에 하나 | 남는 전부 | 해당 장 |
| 남는 질문 — 모임에서 함께 이야기할 것 2~3개 | 1 | null |

🔴 **모티프 단위로 나눈다. 장 단위가 아니다.** 장별로 나누면 줄거리 요약이 된다.
같은 모티프가 여러 장에 흩어져 있으면 그 장들을 한 칸에 묶는다
(`plan` 에 묶은 장을 다 적는다).

`level` 이 **결말을 다룰 범위**를 가른다.

| | 결말 |
|---|---|
| `intro` | 안 말한다 (아직 안 읽은 사람 대상) |
| `working` | 암시까지 |
| `deep` | 다룬다 (다 읽은 모임 대상) — 표지 슬라이드에 **명시**한다 |

## ② 칸 채우기 — 인용이 중심이다

```html
<section>
  <h2>모티프 한 문장</h2>
  <blockquote>원문 인용 (2~4줄)</blockquote>
  <ul><li>해석 1~2개</li></ul>
  <p class="note">3장</p>
</section>
```

- 🔴 **인용은 원문 그대로.** 다듬거나 요약하면 문학에서는 의미가 바뀐다.
  OCR 오탈자는 문맥으로 고치되 **확신 없으면 그대로 두고 `note` 에 표시**한다
- 인용 없는 모티프 슬라이드를 만들지 않는다 — 근거가 없으면 감상일 뿐이다
- 한 슬라이드에 인용 하나. 둘을 나란히 두려면 **대조가 목적**일 때만
- 해석은 **단정하지 않는다.** "…로 읽힌다"·"…일 수 있다" — 문학에 정답을 주면 토론이 닫힌다

분량 상한: `<blockquote>` 4줄 · 각 60자 / `<li>` 2개 · 각 70자 (넘치면 잘려 사라진다)

## ③ 조립

1. **표지에 질문을 둔다.** 책 소개가 아니라 "오늘 같이 생각해 볼 것"
2. `intro`/`working` 이면 **결말 노출이 없는지 전수 확인.** 하나만 새도 발표가 망가진다
3. 모티프 순서를 **이야기 순이 아니라 질문이 깊어지는 순**으로 재배치
4. **남는 질문**은 본문에서 답을 안 준 것만 고른다. 이미 답한 걸 물으면 토론이 안 열린다
5. `countSlides` = 아웃라인 칸 수 확인

## 금지

- 장별 줄거리 요약
- 인용 없는 해석 슬라이드
- 인용을 다듬는 것
- 해석을 정답처럼 단정하는 것
- `intro`/`working` 에서 결말 노출
