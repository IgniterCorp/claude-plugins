# tech-handout — 기술서 → 핸드아웃

> **공통 규약을 먼저 읽는다** → [`_common.md`](_common.md)

발표 때 나눠 주거나 발표 **뒤에 혼자 읽는** 문서. deck 과 역할이 다르다 —
deck 은 말로 채워지는 **뼈대**이고 핸드아웃은 **말이 없어도 완결**이어야 한다.

옵션: `level` · `examples` · `density`

## deck 과 무엇이 다른가 — 이걸 혼동하면 둘 중 하나가 쓸모없어진다

| | deck | handout |
|---|---|---|
| 읽는 상황 | 발표자가 말하는 중 | 혼자, 나중에 |
| 완결성 | 말이 빠진 뼈대 | **문장으로 완결** |
| 코드 | 발췌 14줄 | **전체** (길어도 된다) |
| 분량 | 시간에서 역산 | 내용에서 올라온다 |
| 생략 | 많이 버린다 | 덜 버린다 — 참조용이니까 |

🔴 **deck 을 늘려 쓴 글이 핸드아웃이 아니다.** 슬라이드 불릿을 문장으로 풀어 놓으면
"말로 채워질 자리" 가 빈 채 남아 읽는 사람이 맥락을 못 잡는다.

## ① 아웃라인 — 장 구조를 따르되 묶는다

`density` 가 **몇 장을 한 섹션으로 묶는가**를 정한다.

| `density` | 묶음 | 섹션당 분량 |
|---|---|---|
| `simple` | 3~5장을 한 섹션 | 400~700자 |
| `standard` | 1~2장을 한 섹션 | 700~1,200자 |
| `full` | 한 장을 한 섹션 (긴 장은 둘로) | 1,200~2,500자 |

| 칸 종류 | 수 | `chapterId` |
|---|---|---|
| 머리말 — 이 책이 푸는 문제, 이 글의 범위 | 1 | null |
| **본문 섹션** | `density` 대로 | 묶은 장 중 **대표 장** |
| 용어 사전 | 1 | null |
| 한 장 요약 + 더 읽을 것 | 1 | null |

묶은 섹션의 `plan` 에는 **묶은 장 번호를 모두 적는다** — ②에서 그 장들을 다 받아야 한다.

## ② 칸 채우기 — 섹션 하나는 완결된 글이다

```html
<h2>섹션 제목</h2>
<p>이 섹션이 답하는 질문 한 문장.</p>
<p>본문 — 원리 → 근거 → 함정 순서.</p>
<pre>코드 전체</pre>
<p>코드 설명 — 무엇이 핵심인지.</p>
<blockquote>인용이 필요하면 (원문 그대로)</blockquote>
```

**순서를 지킨다: 원리 → 근거 → 함정.** 함정을 먼저 쓰면 왜 그게 함정인지 모른다.

- **코드는 전체를 넣는다.** deck 과 달리 줄 수 제한이 없다 — 참조용이기 때문이다.
  `white-space: pre-wrap` 이라 긴 줄도 접혀서 PDF 에서 안 잘린다
- 표가 설명보다 짧아지면 표로 쓴다 (비교·대조는 거의 항상 그렇다)
- **각 섹션 끝에 "출처: n장"** 을 남긴다. 책으로 돌아갈 좌표다

**`level` 별 차이**

| | `intro` | `working` | `deep` |
|---|---|---|---|
| 용어 사전 | 필수 · 모든 신규 용어 | 핵심만 | 생략 가능 |
| 본문 | 왜 필요한지로 시작 | 어떻게 쓰는지로 시작 | 내부 동작·대안과의 비교로 시작 |
| 코드 주석 | 줄마다 | 핵심 줄만 | 없음 |

## ③ 조립

1. **머리말** — 이 글의 범위와 **다루지 않는 것**을 적는다. 범위는 뺀 것으로 정해진다
2. **용어 사전** — ②에서 실제로 쓴 용어만 모은다. 안 쓴 용어를 넣지 않는다
3. 섹션 간 **중복 제거** — 묶음이 다르면 같은 설명이 두 번 나온다. 뒤엣것을 앞으로 가리킨다
4. `<section>` 이 **없는지** 확인한다 (있으면 PDF 에서 쪽이 강제로 끊긴다)

## 금지

- deck 불릿을 문장으로 풀어 놓는 것
- 코드를 발췌·생략하는 것 — 여기선 전체를 넣는다
- 다루지 않는 범위를 안 적는 것
- `<section>` 사용
